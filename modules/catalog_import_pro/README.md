# Catalog Import PRO 2.3.1

Автор: CodeCart PRO
Сайт: https://codecartpro.com
Совместимость: CodeCart 3.0.5.2, OpenCart 3.x, ocStore 3.0.4.1, PHP 7.4-8.5, MySQL/MariaDB, InnoDB, utf8mb4.
Внутренний код модуля: `scrapesmart_catalog_import` — сохранён для безопасного обновления предыдущих версий.

Catalog Import PRO — административный модуль безопасного пакетного импорта и потокового экспорта товаров, категорий, производителей и опций через постоянную AJAX-очередь.

ВАЖНО: перед установкой, обновлением, удалением и первым реальным импортом обязательно создайте полный backup файлов сайта и базы данных.

## Что изменено в 2.3.1

- подтверждена совместимость рабочего кода с PHP 7.4-8.5;
- устранён `curl_close()` deprecation PHP 8.5 при безопасной загрузке удалённых изображений без потери освобождения cURL-ресурса на PHP 7.4;
- обновлены версия и сведения о совместимости; логика импорта, очередей, dry run и синхронизации поставщиков не изменялась.

- добавлены индивидуальные правила обработки полей: preserve, overwrite, fill_empty, merge, replace и clear;

- до создания очереди проверяются наличие выбранного ключа, обязательные колонки выбранного профиля и отсутствие двух колонок, сопоставленных в одно поле;

## Безопасное состояние OFF

После установки или миграции модуль принудительно выключен.

Пока статус OFF, заблокированы:

- загрузка и подготовка CSV;
- рабочие AJAX-действия;
- импорт и удаление;
- восстановление и повтор очереди;
- экспорт;
- скачивание изображений;

## Установка

1. Создайте полный backup файлов сайта и базы данных.
2. Откройте «Расширения → Установка расширений».
3. Загрузите `Catalog_Import_Pro_v2.3.1.ocmod.zip`.
4. Откройте «Расширения → Модули» и установите «Импорт каталога PRO».
5. Откройте настройки модуля. Статус после установки будет OFF.
6. Проверьте лимиты CSV, изображений и срок хранения очередей.
7. Включите модуль вручную и сохраните настройки.
8. Первый импорт запустите в тестовом режиме.
9. Проверьте строки review и примените только выбранные.

## Обновление

1. Создайте полный backup файлов сайта и базы данных.
2. Загрузите новый архив через установщик расширений.
3. Откройте главную страницу настроек модуля.
4. Миграция таблиц выполнится автоматически.
5. После миграции модуль останется OFF.
6. Проверьте настройки и включите его вручную.

При ошибке миграции рабочие действия блокируются, а техническая причина записывается в журнал OpenCart.

## Удаление

Удаление модуля удаляет только:

- служебные таблицы очередей, журналов и реестра товаров поставщиков;
- сохранённые временные CSV-файлы;
- настройки модуля.

Товары, категории, производители и опции каталога не удаляются. Перед удалением всё равно создайте backup базы данных.

## Профили импорта

### Свои настройки

Используются выбранные режим, ключ, сопоставление колонок и правила полей.

### Только цены

- принудительно используется режим update;
- принудительно используется строгий ключ;
- обрабатываются только выбранный ключ и `_PRICE_`;
- остальные колонки CSV игнорируются, даже если присутствуют.

### Только остатки

- режим update;
- строгий ключ;
- обрабатываются только ключ, `_QUANTITY_` и `_STOCK_STATUS_ID_`.

### Только цены и остатки

- режим update;
- строгий ключ;
- обрабатываются только ключ, цена, количество и статус наличия.

### Только новые записи

- режим add;
- строгий ключ;
- найденные записи пропускаются;
- отсутствующие записи создаются.

### Только существующие записи

- режим update;
- строгий ключ;
- найденные записи обновляются;
- отсутствующие записи пропускаются.

### Полное добавление и обновление

- режим upsert;
- строгий ключ;
- найденные записи обновляются;
- отсутствующие создаются.

## Режимы

`add` — создать только отсутствующую запись.

`update` — обновить только найденную запись.

`upsert` — обновить найденную или создать отсутствующую.

`delete` — удалить только запись, явно указанную в CSV и найденную по ключу.

Режим delete удаляет только записи, прямо перечисленные в CSV. Для обработки товаров, отсутствующих в новом файле, используется отдельная синхронизация поставщика с обязательным dry run и ручным подтверждением.

## Синхронизация товаров поставщика

Функция обрабатывает товары, которые были в предыдущих подтверждённых файлах конкретного поставщика, но отсутствуют в новом CSV.

Обязательные условия:

- указывается постоянный код поставщика, например `supplier_a`; код автоматически приводится к нижнему регистру и должен оставаться неизменным между файлами;
- используется строгий стабильный ключ SKU, модель, EAN или ID; синхронизация по названию запрещена;
- режим должен быть update или upsert;
- dry run обязателен;
- администратор отдельно подтверждает ограничение поставщиком;
- отсутствующие товары создаются как отдельные строки review со снятым выбором.

Доступные действия:

- не трогать;
- отключить товар;
- обнулить остаток;
- удалить товар штатной моделью OpenCart.

Первый подтверждённый импорт формирует безопасную базовую привязку товаров к поставщику. На первом запуске ранее неизвестные модулю товары не удаляются. Если выбран профиль «Только новые» и товар уже существует, после dry run и подтверждения модуль не изменяет товар, а только регистрирует его связь с поставщиком. Начиная со следующего файла сравнение выполняется только с реестром этого кода поставщика и выбранного ключевого поля.

Товар, присутствующий в CSV даже с ошибкой другой колонки, отсутствующим не считается. Пустой файл без единой строки с действительным ключом не может запустить обработку отсутствующих товаров.

Если после создания review-партии товар снова поступил в более новой партии поставщика, отложенное отключение, обнуление или удаление автоматически отменяется.

Если тот же товар закреплён за другим активным поставщиком, отключение, обнуление остатка и удаление блокируются. После отдельного подтверждения отключается только связь с текущим поставщиком; сам товар и активные связи других поставщиков сохраняются.

## Как определяется существующая запись

Товары:

- `_ID_`;
- `_MODEL_`;
- `_SKU_`;
- `_EAN_`;
- `_NAME_`.

Категории:

- `_ID_`;
- `_NAME_`;
- `_CATEGORY_` — полный путь.

Производители:

- `_ID_`;
- `_NAME_`.

Опции товара:

- `_PRODUCT_ID_`;
- `_PRODUCT_MODEL_`;
- `_PRODUCT_SKU_`;
- `_PRODUCT_NAME_`.

В строгом режиме выбранное ключевое поле обязательно в каждой строке. Пустой ключ является ошибкой. Автоматический переход к модели, SKU, EAN или названию не выполняется.

Резервной стратегии нет. Если выбранный ключ отсутствует или пустой, строка всегда получает ошибку.

Если один ключ соответствует нескольким записям, строка завершается ошибкой. Случайная запись не выбирается.

Дубли одного логического ключа внутри партий товаров, категорий и производителей запрещены. Для опций повтор ключа товара разрешён, поскольку один товар может занимать несколько строк с разными значениями опций.

## Сопоставление колонок поставщика

В поле сопоставления укажите по одной связи в строке:

```text
Артикул поставщика=_SKU_
Цена продажи=_PRICE_
Остаток=_QUANTITY_
Бренд=_MANUFACTURER_
Раздел=_CATEGORY_
Фото=_IMAGE_
```

Исходный заголовок сравнивается без учёта регистра, включая кириллические русские и украинские буквы даже на сервере без mbstring. Неуказанная колонка сохраняет собственное имя и будет распознана только если оно уже поддерживается модулем.

Если две исходные колонки сопоставлены в одно целевое поле, партия отклоняется до создания очереди: неоднозначное перезаписывание запрещено.

Ограничение: не более 200 правил сопоставления в одной партии.

## Индивидуальные правила обработки полей

В интерфейсе для каждого поддерживаемого поля показан отдельный список политики. Текстовые правила вручную вводить не требуется.

Поддерживаемые политики:

`preserve` — никогда не изменять поле, даже если колонка есть в CSV.

`overwrite` — записать переданное значение. Для одиночных полей это основное штатное поведение.

`fill_empty` — записать значение только если существующее поле или коллекция пусты.

`merge` — добавить или объединить данные. Для описаний, тегов и метаданных текст добавляется без повторения; для коллекций выполняется объединение без дублей.

`replace` — полностью заменить коллекцию переданными данными.

`clear` — явно очистить поле или коллекцию независимо от настройки «Игнорировать пустые поля».

Если колонки нет в CSV, соответствующее поле не изменяется. Политики применяются к изменяемым данным; ключи сопоставления и идентификаторы опций используются только для поиска записи и намеренно не имеют политики перезаписи.

Если колонка есть, но ячейка пустая и включено «Игнорировать пустые поля», существующее значение сохраняется, кроме явного правила clear. Политика clear недоступна для обязательных названий, модели товара и даты доступности. Выбранный ключ нельзя очищать; в режимах создания его также нельзя помечать «Не трогать».

## Тестовый режим и выбор строк

Тестовый режим выполняет поиск записи, полную валидацию, проверку связей, изображений, SEO URL и планируемого действия без изменения каталога.

После завершения успешные строки получают статус review.

Доступны:

- выбор или снятие выбора с каждой строки;
- «Выбрать все»;
- «Снять выбор»;
- применение только выбранных строк;
- фильтр по статусу;
- поиск по ключу, сообщению и предупреждениям;
- серверная пагинация;
- полный CSV-отчёт;
- повтор строк со статусом error.

Невыбранные строки при применении получают статус skipped и не меняют каталог.

CSV-отчёт включает исходный нормализованный payload JSON, поэтому ошибочную строку можно восстановить, исправить в исходном файле и загрузить заново.

## Коммерческие данные товара

Экспорт записывает скидки, акции, бонусы и периодические платежи в JSON. Такой CSV можно импортировать обратно без преобразования.

Также поддерживается компактный ручной формат.

### Скидки `_DISCOUNTS_`

Компактный формат:

```text
customer_group_id:quantity:priority:price:date_start:date_end|...
```

Пример:

```text
1:5:1:90.00:2026-01-01:2026-12-31
```

### Акции `_SPECIALS_`

```text
customer_group_id:priority:price:date_start:date_end|...
```

### Бонусы `_REWARDS_`

```text
customer_group_id:points|...
```

### Периодические платежи `_RECURRING_`

```text
recurring_id:customer_group_id|...
```

Проверяются существование группы покупателей, существование схемы периодических платежей, неотрицательные цены и баллы, количество скидки, приоритеты и диапазоны дат.

`_NAME_RU-RU_`

`_NAME_EN-GB_`

`_DESCRIPTION_LANG=1_`

## Изображения

OpenCart хранит относительный путь внутри `DIR_IMAGE`. Полный HTTP URL никогда не записывается в поле image как локальный путь.

При включённом скачивании модуль:

- разрешает только HTTP и HTTPS;
- запрещает URL с логином, паролем и нестандартным портом;
- блокирует localhost, приватные, служебные и зарезервированные IP-адреса;
- повторно проверяет адрес назначения после перенаправления;
- включает проверку SSL-сертификата;
- ограничивает размер ответа;
- проверяет HTTP-код;
- проверяет MIME и реальную сигнатуру файла;
- разрешает JPG, JPEG, PNG, GIF, WebP и AVIF;
- записывает файл атомарно;
- не позволяет выйти за пределы `image/catalog`.

## SEO URL

Указывается только конечный slug:

```text
demonstratsiinyi-tovar
```

Запрещены:

- домен;
- полный или вложенный путь;
- начальный и конечный `/`;
- `.html`;
- конфликтующий slug для другого query в том же магазине и языке.

Экспорт создаёт отдельные колонки для каждого магазина и языка, например:

`_SEO_KEYWORD_STORE=1_LANG=2_`

## Очередь и восстановление

CSV сохраняется в постоянном каталоге `DIR_STORAGE/scrapesmart_catalog_import/` и разбирается порциями.

Служебные таблицы используют InnoDB и utf8mb4.

Подготовка каждой порции выполняется транзакционно. Смещение файла и строки очереди фиксируются вместе. При аварии вся текущая порция откатывается и безопасно читается повторно.

Каждая CSV-строка уникальна в рамках партии по `batch_id + csv_row_number`.

Обработчик атомарно захватывает строки по worker token. Lease по умолчанию составляет 120 минут и обновляется перед обработкой каждой следующей строки захваченной порции. Ручное восстановление возвращает только действительно истёкшие processing-записи.

Пауза прекращает отправку новых AJAX-запросов. Текущий запрос завершается штатно.

Отмена блокирует новые строки. Уже начатую транзакцию нельзя безопасно оборвать посередине, поэтому текущая порция может завершиться.

## Экспорт

Экспорт выполняется потоково и не собирает весь каталог в памяти.

Поддерживаются разделители:

- `;`;
- `,`;
- табуляция;
- `|`.

Значения, начинающиеся с `=`, `+`, `-` или `@`, защищаются от CSV Formula Injection.

Экспорт является переносом поддерживаемых полей, но не заменяет резервную копию базы данных. Данные неизвестных сторонних таблиц в CSV не включаются.

## Безопасность

- user_token сверяется с токеном текущей сессии;
- изменяющие действия принимают только POST;
- проверяются права access и modify;
- SQL-идентификаторы выбираются только из внутренних whitelist;
- числа приводятся к типам;
- строки экранируются драйвером OpenCart;
- опасные массовые действия проходят dry run и выбор строк;
- модуль не содержит eval, обфускации, shell-команд или скрытой загрузки удалённого PHP-кода;
- постоянные данные не хранятся в cache;
- frontend-ресурсы не подключаются.

## Ограничения

Синхронизация отсутствующих товаров работает только для товаров, ранее зарегистрированных модулем под тем же кодом поставщика и тем же ключевым полем. Она не пытается автоматически присвоить поставщику весь каталог магазина.

Ошибочную строку нельзя редактировать прямо внутри таблицы очереди. Скачайте отчёт, исправьте исходный CSV и создайте новую тестовую партию. Это исключает скрытое изменение исходных данных после проверки.

Нестандартные поля и таблицы сторонних модулей требуют отдельного адаптера.
