# Import Export Pro 3.7.0

Автор: CodeCart PRO  
Сайт: https://codecartpro.com

## Назначение

Import Export Pro — административный модуль импорта, экспорта и синхронизации товаров для ocStore 3.0.4.1 и OpenCart 3.x. Поддерживаются CSV, XLSX, XML/YML, JSON и HTML-таблицы, профили поставщиков, наценки, изображения, защищённые публичные фиды и экспорт для маркетплейсов.

## Совместимость

- CodeCart 3.0.5.2;
- ocStore 3.0.4.1;
- OpenCart 3.x;
- PHP 7.4–8.5;
- MySQL/MariaDB, InnoDB, utf8mb4;
- языки интерфейса: en-gb, ru-ru, uk-ua.

## Обязательное предупреждение

Перед установкой, обновлением, импортом или синхронизацией сделайте полный backup файлов сайта и базы данных. Первый запуск каждого нового профиля выполняйте на тестовой копии магазина и обязательно проходите dry run.

После установки или обновления модуль остаётся выключенным. Пока статус OFF, импорт, cron и публичные фиды заблокированы.

## Безопасная архитектура импорта

Полный административный импорт всегда проходит через постоянную очередь InnoDB:

1. Источник нормализуется в канонический CSV.
2. CSV разбирается порциями без создания дублей строк после аварии.
3. Каждая строка получает постоянный статус, номер, ключ и JSON-снимок данных.
4. Выполняется dry run без изменения каталога.
5. Успешные строки переходят в статус review.
6. Администратор выбирает строки и подтверждает применение.
7. Изменение товара и завершение строки фиксируются одной транзакцией.

Используются worker token, lease, heartbeat, блокировка одного товара от параллельной обработки, восстановление зависших задач, повтор только ошибок, пагинация, поиск и CSV-отчёт.

## Строгое определение товара

Профиль использует только один выбранный ключ:

- product_id;
- model;
- SKU;
- UPC;
- EAN;
- JAN;
- ISBN;
- MPN.

Резервного поиска по другому полю нет. Пустой ключ является ошибкой строки. Если найдено несколько товаров с одинаковым значением ключа, импорт блокируется и требует устранить дубликаты.

## Режимы запуска

- Полный импорт — создание и/или обновление согласно настройкам профиля.
- Только цены — сервер обрабатывает только ключ и price.
- Только остатки — сервер обрабатывает только ключ, quantity и stock_status_id.
- Цены и остатки — сервер обрабатывает только перечисленные поля.
- Только новые — найденные товары пропускаются, отсутствующие создаются.
- Только существующие — новые товары не создаются.

Быстрые режимы являются серверными ограничениями: лишние колонки источника не могут изменить другие данные.

## Индивидуальные политики полей

Для каждого поддерживаемого поля можно установить:

- По умолчанию — безопасное стандартное поведение поля.
- Не трогать — сохранить значение магазина.
- Перезаписать — применить значение источника.
- Заполнить только пустое — не заменять уже заполненные данные.
- Добавить / объединить — дополнить тексты или коллекции без удаления существующих данных.
- Полностью заменить — заменить коллекцию данными источника.
- Очистить — явно очистить поле или коллекцию.

Отсутствующая колонка никогда не очищает данные. Пустая ячейка учитывается отдельно настройкой «Игнорировать пустые поля». Очистка обязательного ключа и критичных обязательных полей блокируется.

## Поддерживаемые данные товара

Импорт и безопасное сохранение включают:

- основные идентификаторы, модель, артикулы и расположение;
- мультиязычные названия, описания, теги и метаданные;
- Meta H1 и noindex ocStore;
- цену, баллы, остаток, минимум, списание, статус наличия;
- налог, доставку, вес, размеры и классы единиц;
- производителя и категории;
- главную категорию ocStore;
- Google Product Category;
- основное и дополнительные изображения;
- магазины;
- SEO URL;
- атрибуты;
- опции и значения опций;
- фильтры и загрузки;
- связанные товары и статьи;
- макеты;
- скидки, акции, бонусные баллы и периодические платежи.

Данные сторонних модулей с собственными таблицами требуют отдельного адаптера.

## Опции

Поддерживаются два формата.

Компактный формат поставщика:

`Опция:Значение:Цена:Префикс:Количество:Списывать:Обязательная`

Несколько значений разделяются `|`, `;` или новой строкой.

Пример:

`Цвет:Красный:0:+:10:1:1|Цвет:Синий:50:+:5:1:1`

Структурированный JSON используется расширенным экспортом модуля и поддерживает тип, текстовое значение, обязательность, изображения и порядок значений, количество, списание, цену, баллы, вес и префиксы.

## Коммерческие коллекции

Скидки, акции, награды и периодические платежи передаются JSON-массивами. ID групп покупателей, схем подписки и других связанных сущностей строго проверяются. Недействительная ссылка останавливает строку и откатывает её транзакцию.

## Поставщики и отсутствующие товары

Для синхронизации задайте постоянный supplier_code и стабильный ключ SKU, model, EAN или другой технический идентификатор.

Первый подтверждённый импорт создаёт базовый реестр поставщика и не выполняет массовых действий над отсутствующими товарами. На последующих полных импортах отсутствующие позиции формируются как отдельные review-строки и по умолчанию не выбраны.

Доступные действия:

- ничего не делать;
- отключить товар;
- обнулить остаток;
- удалить товар.

Если товар связан с другим активным поставщиком, отключение, обнуление и удаление блокируются; отключается только связь с текущим поставщиком. Товары, отфильтрованные правилами профиля, отмечаются как присутствующие и не считаются исчезнувшими.

Синхронизация отсутствующих товаров по названию запрещена.

## Изображения

Удалённые изображения проверяются по протоколу, DNS/IP, SSL, размеру, MIME и фактической сигнатуре. Локальные, частные, loopback и служебные адреса блокируются. Путь сохранения ограничен каталогом `image/catalog/import_pro` и его подкаталогами. Запись выполняется безопасно, а удалённый URL не записывается как локальный путь OpenCart.

## Очистка HTML

Импортируемые описания очищаются от script, iframe, object, embed, form, SVG, MathML, srcdoc, обработчиков событий, опасных URL-схем и активного CSS. Разрешённые HTML-теги и атрибуты сохраняются.

## Экспорт

Поддерживаются:

- CSV;
- XLSX;
- XML;
- JSON;
- Rozetka YML;
- Epicentr XML;
- Hotline XML;
- Prom.ua YML;
- Price.ua YML;
- Facebook/Instagram CSV;
- Pinterest CSV;
- TikTok CSV.

CSV-экспорт выполняется порциями и передаётся потоком, поэтому не загружает весь каталог в память. CSV защищён от Formula Injection. XLSX, XML, JSON и маркетплейс-фиды формируются как документ и требуют больше памяти; для больших каталогов используйте фильтры и лимиты либо CSV.

Расширенный экспорт стандартных данных формирует значения опций и коммерческие коллекции в JSON, пригодном для обратного импорта.

## Cron

Cron намеренно разрешён только для существующих товаров и режимов:

- price_only;
- quantity_only;
- price_stock.

Cron не создаёт товары и не изменяет названия, описания, категории, изображения, SEO URL, атрибуты или опции. Полный импорт требует административного dry run и ручного подтверждения.

Для Mirohost минимальный интервал запуска — 5 минут. Используйте поля панели Mirohost и URL, показанный в разделе Cron модуля.

## Установка

1. Сделайте полный backup сайта и базы данных.
2. Загрузите архив через «Расширения → Установка расширений».
3. Обновите модификаторы, если это требуется конфигурацией магазина.
4. Установите модуль в «Расширения → Расширения → Модули».
5. Откройте настройки. Модуль будет OFF.
6. Проверьте вкладку диагностики.
7. Настройте профиль, сопоставьте колонки и сохраните его.
8. Включите модуль вручную только после проверки настроек.
9. Выполните dry run на тестовой копии и примените только проверенные строки.

## Обновление

При обновлении с предыдущей версии замените файлы через установщик. При первом открытии модуль выполняет идемпотентную миграцию схемы и остаётся OFF. Профили и журналы сохраняются. Повторно проверьте сопоставление колонок и выполните dry run.

## Удаление

По умолчанию удаление расширения не удаляет постоянные таблицы профилей, очередей и реестров. Полное удаление данных выполняется только при заранее включённой настройке удаления данных. Перед этим обязательно сделайте backup базы данных.

## Ограничения

- Полноценный интеграционный тест требуется на копии конкретного магазина с его Events, OCMOD и сторонними таблицами.
- Форматы маркетплейсов могут требовать индивидуального сопоставления категорий и атрибутов по правилам конкретной площадки.
- Публичные фиды защищены токеном, но токен необходимо хранить как секрет и периодически менять при подозрении на утечку.
