# Проверка от 8 октября 2026

Результат функциональной доработки: подготовлены локальные архивы для проверки на копии магазина. Статус полного коммерческого выпуска: **not ready**. Проверенные изменения нельзя приравнивать к полной проверке действующего магазина, всех сторонних расширений и License Server PRO.

## Выполнено

- Import/Export 3.6.9: inlineStr и rich text в XLSX, пустые промежуточные колонки, абсолютные пути листов, отказ при отсутствующем листе, сохранение ведущих нулей, поиск по точному названию выбранного языка, отказ при неоднозначных идентификаторах в cron.
- Import/Export: распознавание текстового количества, настраиваемый остаток для «в наличии», сохранение неизвестного остатка, режим цены/наличия учитывает выключенное обновление количества. Новые товары очереди выключены по умолчанию.
- Supplier Sync Parser 1.6.3: отрицательное наличие проверяется прежде положительного, специфичные правила stock_map имеют приоритет перед короткими подстроками, числовые SKU/EAN сохраняются. Можно оставить остаток и отдельно оставить stock_status_id.
- Supplier: профиль Spilna Meta, реальные XPath цены, артикула, наличия, описания, производителя, характеристик и фото. Названия категорий извлекаются из хлебных крошек; миниатюры Prom заменяются полными фото.
- Supplier: языковые варианты проверяются по ID Prom, артикулу и фактическому html/@lang. Украинский редирект не сохраняется как русский перевод. Отсутствующие описания не копируются без настройки.
- Supplier: создание выключенной категории для новых товаров, повторное использование этой категории, главная категория ocStore. Учитываются обязательные nix_supplier_id, nix_supplier_product_id, price_purchasing, price_rrp, meta_h1. Поля ImportXML получают нейтральные значения, не чужую связь поставщика.
- Supplier: транзакции при создании и обновлении, откат при ошибке. Дополнительно в истории есть возврат успешно изменённых цены/количества/stock_status_id: он проверяет текущие значения, блокирует конфликт с последующей правкой и повторный возврат, оставляет запись в журнале.
- Supplier: OFF-проверки в рабочих методах до SQL/HTTP. Открытие страницы не запускает установку/миграции; обновление схемы при необходимости выполняется после проверенного POST. Для install/uninstall добавлены проверки токена и прав.
- ImportXML 1.4.2: безопасная загрузка фото, ограничение размера, проверка формата, публичные адреса, DNS pinning, проверка каждого редиректа и атомарное сохранение. В URL нельзя навязать исполняемое расширение файла.
- PDF Rewolt: отдельный подготовительный инструмент; CSV, оптовая/розничная цена, исходное наличие, фото, отчёт. Другие макеты PDF не объявляются поддержанными автоматически.

## Доказательства

- Все 36 PHP-файлов четырёх модулей проходят синтаксическую проверку на PHP 7.4, 8.0, 8.1, 8.2, 8.3, 8.4, 8.5. На каждой версии пройдены 15 групп тестов; сообщения Deprecated/Warning/Fatal/Parse делают проверку неуспешной.
- XLSX проверен отдельно для admin и catalog/cron: shared strings, inline strings, rich text, пустые промежуточные колонки, выбранный лист, отсутствующий лист, ведущие нули. Дублирующий обработчик cron исправлен после воспроизведения потери текстового артикула через настоящий HTTP cron.
- Девять Twig-шаблонов проходят компиляцию на каждой из семи версий PHP: Twig 2.15.6 для 7.4/8.0 и совместимый локальный Twig для 8.1–8.5.
- Две изменённые страницы отрендерены; встроенный JavaScript проверен Node.js, проверена принадлежность новых полей форме сохранения. Дополнительно страницы проверены в браузере локального магазина: на ширинах 1366 и 390 px документ не выходит за экран. Это не тест каждого состояния всех вкладок.
- MariaDB 10.11.16, STRICT_ALL_TABLES: исходный Supplier 1.6.1 падает на отсутствующем обязательном nix_supplier_id; обновлённый создаёт выключенный товар, сохраняет SKU «0001», разные описания UA/RU и пустое EN.
- На MariaDB подтверждены главная категория, повторное использование скрытой категории, сохранение профиля и настроек наличия, повторная установка, удаление с сохранением данных, переустановка, откат искусственно вызванных ошибок создания/обновления, обновление цены с сохранением остатка, возврат завершённого изменения цены/наличия и отказ при конфликте/повторном возврате.
- Для HTML использованы две локальные копии реально полученных страниц Spilna Meta. Русский URL перенаправлялся на украинский. Отдельный русский текст проверен синтетическим тестом; наличие настоящего русского перевода у поставщика не заявляется.
- PDF: извлечено 237 позиций, 222 фотографии. Для отсутствующих фото и приблизительного количества есть записи отчёта. Фотография первой строки визуально проверена; соответствие всех 222 фотографий вручную не проверялось.
- ZIP проверяется повторным чтением, CRC, наличием install.xml/upload, совпадением версии и SHA-256. Детали автоматических проверок находятся в dist/verification.json.

## Проверка на изолированной копии gontagro

Код сайта получен из предоставленного пользователем backup, схема и каталог из его дампа. Сервер доступен только на 127.0.0.1. Покупатели, заказы, исходные администраторы, ключи и внешние рабочие интеграции не переносились в стенд. Это не установка на действующий сайт. OCMOD/Events отключены; часть исходных настроек и файлов темы отсутствует в изолированном комплекте.

- Реальные POST/AJAX: установка, сохранение профиля и правил, повторное открытие, отключенное состояние, проверка карточки Rewolt по HTTPS с проверкой сертификата, очередь, предпросмотр, подтверждение создания.
- Создан выключенный тестовый товар: производитель, украинское описание, 7 характеристик, главное фото и 6 дополнительных фото, скрытая категория. Изображения проверены как настоящие файлы. Пустые языки не выдаются за перевод.
- Поиск по артикулу и ручной выбор существующего товара выполнены через настоящий admin AJAX. После изменения SKU и MPN локального товара сохраненная связь с URL поставщика снова нашла product_id. Настоящий catalog cron обновил цену с 10000 до 9094, сохранив количество 33 и status=0.
- Multipart-загрузка CSV и XLSX с ПК выполнена через uploadSource. Профили сохранены, строки обработаны в предпросмотре, выбраны и подтверждены, затем обработаны реальной очередью. Обновлены цены 8888 и 7777; количество из файла 999 не применено при update_quantity=0, осталось 33. status=0 сохранен. Отдельно оба файла успешно прошли catalog cron.
- В стандартной таблице product_attribute нет product_attribute_id: убран запрос этого неиспользуемого столбца из снимка товара. Ошибка воспроизведена на реальном admin предпросмотре и исправление повторно проверено тем же сценарием.
- Выключенный товар возвращал 404. После временного включения только тестового товара карточка UniShop2 выводила фото, описание, характеристики, цену 7777 и наличие; затем товар снова выключен. Внешний вид и все скрипты темы не объявляются полностью проверенными.
- MariaDB: повторно пройдены 29 проверок создания, транзакций, главной категории, повторной установки, сохранения связей, отката цен/остатков, cron и блокировок. Исходный Supplier 1.6.1 воспроизводимо падает на обязательном nix_supplier_id; обновленный проходит.
- Spilna Meta, Sazagro и Rewolt имеют профили XPath, проверенные на сохраненном реальном HTML. Полный обход всех товаров не проверен. Petroline возвращает JavaScript-защиту: PHP HTML-парсинг не объявляется готовым; нужен доступный фид или отдельный браузерный адаптер.
- Автоматический плановый обход поддержан для уже связанных HTML-карточек. Для feed-профилей автоматическое создание периодической очереди пока не реализовано; используйте Import/Export для планового обновления из прайса. Новые товары создаются вручную после проверки.

## Что остаётся до production-ready

1. Полностью проверить сторонние OCMOD/Events и восстановить комплект среды UniShop2 на копии магазина. В текущем изолированном стенде они отключены. Для включаемых Twig-файлов темы использован только локальный FilesystemLoader; он не входит в модуль. Данные карточки отрендерены, полная визуальная и интерактивная совместимость темы не подтверждена. Проверить весь обход каталога, пагинацию, остановку/восстановление очереди и одновременные HTTP-запросы.
2. Проверить реальный XLSX: предоставленный файл по указанному пути отсутствует. Тесты покрывают обнаруженные дефекты чтения, но не конкретную структуру отсутствующего прайса.
3. Завершить коммерческий лицензионный стандарт: в проверенных исходных версиях не подтверждена полноценная подписанная lifetime-лицензия. В этой функциональной доработке новая система лицензирования не внедрялась; активация/блокировка/перенос домена на настоящем License Server не проверялись.
4. Возврат в истории Supplier покрывает только цену/количество/stock_status_id. Для возврата описаний, характеристик, фото, создания товаров и завершённых файловых импортов нужны дополнительные постоянные снимки и отдельный интерфейс проверки. Массовое удаление новых товаров вместо отката не выполняется.
5. Прочие обязательные нестандартные поля магазина должны иметь отдельный адаптер. Поддержка выявленных полей не означает поддержку любой произвольной модификации схемы.
6. ImportXML остаётся модулем существующих XML-связей и не заменяет универсальный HTML-парсер. Полное раздельное управление его ценой/наличием/публикацией не переделано; для нового процесса используйте два основных модуля.

## Сравнение назначения

Профили файлового импорта и HTML-обход поставщика решают разные задачи. У [Universal Import/Export Pro](https://www.opencart.com/index.php?route=marketplace/extension/info&extension_id=27350) заявлены CSV/XML/XLS/XLSX/JSON и другие файлы; это полезный ориентир по форматам, но само наличие файлового импорта не доказывает поддержку обхода произвольного сайта. Для текущего процесса сохраняются два модуля с прежними настройками, таблицами и кодами; отдельный Catalog Import не требуется ставить параллельно основному Import/Export.

Данные магазинов, дампы, прайсы поставщиков и секреты находятся только локально и не включаются в исходный репозиторий.
