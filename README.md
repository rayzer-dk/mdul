# CodeCart PRO — импорт и синхронизация поставщиков

Перед установкой или обновлением обязательно сделайте полный backup сайта и базы данных. Сначала проверяйте модуль на копии магазина.

Для текущей задачи используются два отдельных модуля:

| Модуль | Назначение |
|---|---|
| Import/Export Pro 3.7.0 | Прайсы CSV/XLSX/XML/YML, сопоставление полей, обновление цен и количества, новые товары из файлов |
| Supplier Sync Parser Pro 1.6.4 | HTML поставщиков, очередь обхода, предпросмотр, ручное сопоставление, фото, описание, характеристики, новые выключенные товары |
| ImportXML Clean Pro 1.4.3 | Поддержка существующих XML/YML-профилей; исправлена загрузка изображений |
| Catalog Import Pro 2.3.1 | Сохранён исходный самостоятельный CSV-импортер. Его очередь уже используется внутри Import/Export; для нового процесса отдельная установка не требуется |

Модули сохраняют прежние module_code и таблицы. Физического слияния и автоматической миграции настроек или лицензий нет. Четыре архива одновременно для этой задачи устанавливать не нужно.

## поставщика HTML A

В Supplier Sync Parser откройте новый профиль кнопкой **поставщика HTML A**. Профиль выключен; автоматическое применение и автоматическое создание выключены. Сначала выберите язык магазина, статус наличия, формулу цены и категорию, сохраните профиль и проверьте одну карточку. Затем включите модуль и профиль вручную, запустите обход и примените выбранные строки предпросмотра.

Условный остаток для текстового «в наличии» настраивается, по умолчанию 100. Явное числовое количество имеет приоритет. Неизвестное наличие сохраняет текущий остаток. Обновление количества можно отключить; обновление stock_status_id регулируется отдельно в парсере. Статус публикации существующего товара из наличия автоматически не меняется.

Поле категории новых товаров создаёт одну выключенную корневую категорию. Принудительная категория по ID имеет приоритет. Новые товары по умолчанию выключены. Похожие названия проверяются вручную; неоднозначный артикул нельзя автоматически привязать к первому найденному товару.

В истории есть кнопка возврата цены и остатка. Она доступна для завершённых обновлений и требует подтверждения. Если текущие значения отличаются от импортированных, возврат отменяется. Возврат не удаляет новые товары и не восстанавливает описания/фото/характеристики. Очистка истории удаляет возможность такого возврата, поэтому сохраняйте журнал на нужный срок.

Профиль Prom использует реальный язык HTML-страницы. Если русская ссылка перенаправляется на украинскую, русский перевод не создаётся. Для отсутствующих языков описание остаётся пустым, если явно не разрешено копирование всех языков. Копирование не является переводом. Название используется как запасное значение для карточки.

## Прайсы

Создайте отдельный профиль на каждого поставщика. Выберите model, SKU, UPC, EAN, JAN, MPN, ISBN или точное название в нужном языке. Настройте соответствие колонок и цену: розница, закупка или формула наценки. Артикулы с ведущими нулями должны оставаться текстом. Менять собственные артикулы следует только после проверки соответствия; для дальнейшей синхронизации предпочтительна постоянная связь поставщик → product_id.

В режиме «цена + наличие» выключение обновления количества сохраняет остаток. Неизвестный текст количества сохраняет значение, а `> 10` нормализуется в нижнюю границу 10. Исходное приближённое количество должно оставаться в отчёте поставщика.

PDF напрямую в PHP-модуль не добавлен: `tools/prepare_rewolt_pdf.py` подготавливает конкретный табличный формат поставщика HTML C в CSV и изображения. Нужен Python с pdfplumber и поддержкой рендеринга PDF. Другие макеты PDF требуют отдельного адаптера.

```powershell
python tools/prepare_rewolt_pdf.py "supplier_price.pdf" "prepared_price" --price retail --approximate lower_bound
```

Из `upload/image` перенесите фотографии в каталог `image` тестового магазина. Импортируйте `products.csv` с разделителем `;`, сначала в предпросмотр. `price` — выбранная цена, `purchase_price` — опт, `retail_price` — розница. Для новых товаров `status=0`. Для обновления существующих выбирайте режим только цены/наличия: поле status из этого файла применять к существующим товарам не нужно.

`--approximate fixed --assumed-quantity 100` явно заменяет приблизительное количество своим. `--approximate keep` сохраняет существующий остаток вместо его обновления. Исходное значение находится в stock_raw и review.json. Полного описания и переводов в данном PDF нет.

## Проверка и сборка

Целевая среда: ocStore 3.0.4.1 / OpenCart 3.x, PHP 7.4–8.5, MySQL/MariaDB. Диапазон изменён по требованию пользователя 08.10.2026. Синтаксис 36 PHP-файлов и 15 групп тестов проверены на каждой из семи версий PHP. Это не подтверждение совместимости всех сторонних расширений магазина. Проверки и их ограничения перечислены в `docs/VERIFICATION_RU.md`. Полную совместимость всех сторонних Events/OCMOD, лицензионную активацию и работу на действующем магазине нельзя подтвердить только локальными тестами.

```powershell
python tools/check_and_package.py --php-root "путь/к/engines/php" --output "dist"
```

Исходный XLSX «Прайс ЖОВТЕНЬ 2026 р..xlsx» по предоставленному пути не найден; его реальная структура пока не проверена. Дампы, прайсы, фотографии поставщика, локальные пароли и настройки магазинов не публикуются в Git.

## Ручная привязка и загрузка с ПК

Supplier Sync Parser: в предпросмотре найдите товар по названию или одному из семи кодов, проверьте цену и выберите товар. Привязка поставщик → product_id хранится в постоянной БД. Последующие обновления используют ее даже после изменения вашего SKU/MPN. Неоднозначные совпадения требуют ручной проверки.

Import/Export: выберите CSV/XLSX на ПК, загрузите файл, сохраните профиль соответствия колонок, выполните предпросмотр и подтвердите выбранные строки. Для быстрого обновления используйте режим цены/наличия. Отключение обновления количества сохраняет остаток. Cron использует сохраненный профиль и источник; новый файл с ПК нужно загрузить вручную, а для автоматического получения прайса нужен доступный URL источника.

Профили HTML: поставщика HTML A, поставщика HTML B, поставщика HTML C. Для поставщика с JavaScript-защитой нужен доступный фид или отдельный адаптер защиты. Полная поддержка всех карточек и пагинации каждого сайта пока не подтверждена. Плановый Supplier cron обновляет связанные HTML-карточки; новые товары проходят ручную проверку. Плановое обновление файлов выполняйте через Import/Export.
